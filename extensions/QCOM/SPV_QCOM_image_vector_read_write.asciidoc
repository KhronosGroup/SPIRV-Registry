Dependencies
------------

This extension is written against the SPIR-V Specification,
Version 1.6 Revision 6.

This extension requires SPIR-V 1.4.

Overview
--------

This extension introduces two vector read/write instructions on images along with new image formats.

Extension Name
--------------

To use this extension within a SPIR-V module, the following
*OpExtension* must be present in the module:

----
OpExtension "SPV_QCOM_image_vector_read_write"
----

New Capability
--------------

This extension introduces a new capability:

----
VectorImageOperationsQCOM
----

New Image Formats
-----------------

The extension adds the following new image formats.

----

NV12YQCOM
NV12UVQCOM

CompressedRGBxQCOM

CompressedNV12YQCOM
CompressedNV12UVQCOM

New Instructions
----------------

Instructions added under the *VectorImageOperationsQCOM* capability:

----

Instructions
~~~~~~~~~~~~

Modify Section 3.3.10, "Image Instructions", adding before OpImageSampleFootprintNV:

[cols="1,1,6*3",width="100%"]
|====
6+|*OpImageVectorReadQCOM* +
 +
Loads the specified component of each of the four adjacent texels
according to the specified access shape and
returns them as a vector of four components.

_Result Type_ is a vector type with four components. The element type is one of 32-bit *floating-point* type,
16-bit *floating-point* type, and 32-bit signed/unsigned *integer* type.

_Texture Sampled Image_ must be an object whose type is OpTypeSampledImage. The MS operand of the 
underlying OpTypeImage must be 0.  The Sampled operand of the OpTypeImage is defined by the execution environment.

_Coordinate_ must be a vector of *floating-point* type, whose vector size is 2.

_Component Id_ must be a 32-bit *integer* type scalar and be one of 0, 1, 2, and 3 which correspond to 
_R_, _G_, _B_, and _A_, respectively, of the _RGBA_ channel order.

_Shape_ is the read access shape and is either AccessShape4x1QCOM or AccessShape2x2QCOM. See <<AccessShape,*Access Shape*>>.

For AccessShape2x2QCOM, the base point specified by _Coordinate_ is the upper
left corner of the 2x2 vector. Value 0 read is the value at the lower left corner. 

For AccessShape4x1QCOM, value 0 read is the value located at the base point _Coordinate_.

[cols="1,1,7*3",width="100%"]
|====
7+a|*OpImageVectorWriteQCOM* +
 +
Write multiple values into the specified image at the adjacent locations
according to the specified access shape.

_Image_ must be an object whose type is OpTypeImage.  The type must not have the Unknown image format.
The behavior is undefined if the type has the image format that is not supported.
The Sampled operand of the OpTypeImage is defined by the execution environment.

_Coordinate_ must be a vector of integer type whose vector size is 2.

_Shape_ is the write access shape. See <<AccessShape,'Access Shape'>>.
AccessShape2x1QCOM requires no additional operand. 
AccessShape3x1QCOM requires one additional operand; a total of three values are written.
AccessShape4x1QCOM and AccessShape2x2QCOM require two additional operands; a total of four values are written.

Value 0 is the value located at the base point _Coordinate_.

_Format_ is the image format associated with _Image_. See <<ImageFormat,'Image Format'>>.

_Values_ depend on the <<ImageFormat,image format>> associated with _Image_.

 * 32-bit / 16-bit floating point values for NV12YQCOM, P010YQCOM, TP10YQCOM, CompressedNV12YQCOM, CompressedP010YQCOM, and
CompressedTP01YQCOM 

 * vectors of 32-bit / 16-bit floating point values whose lengths are 2 for NV12UVQCOM, P010UVQCOM, TP10UVQCOM, CompressedNV12UVQCOM, CompressedP010UVQCOM, and CompressedTP10UVQCOM

 * 32-bit floating point scalar values for UNORM_MIPI10QCOM and UNORM_MIPI12QCOM

 * 32-bit integer scalar values for UNSIGNED_MIPI10QCOM and UNSIGNED_MIPI12QCOM

Validation Rules
----------------

An OpExtension must be added to the SPIR-V for validation layers to check
legal use of this extension:

----
OpExtension "SPV_QCOM_image_vector_read_write"
----

*OpImageVectorWriteQCOM* accepts only the image formats defined in the 
SPV_QCOM_image_vector_read_write extension. The behavior is undefined if NV12QCOM,
P010QCOM, or TP10QCOM is passed as _Format_ to *OpImageVectorWriteQCOM*.

The number of the _Values_ operands and their types passed to *OpImageVectorWriteQCOM*
must be consistent to the <<ImageFormat,image format>> specified with the _Format_ operand.

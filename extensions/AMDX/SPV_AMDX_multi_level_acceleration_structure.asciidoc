Dependencies
------------

This extension is written against the Unified SPIR-V Specification,
Version 1.6, Revision 4.

This extension requires SPIR-V 1.4.

This extension requires SPV_KHR_ray_tracing or SPV_KHR_ray_query.

:RayQueryUrl: https://htmlpreview.github.io/?https://github.com/KhronosGroup/SPIRV-Registry/blob/main/extensions/KHR/SPV_KHR_ray_query.html

Overview
--------

This extension adds functionality to ray tracing pipelines and ray queries to
allow querying properties of each individual instance in the chain of
acceleration structure instances that led to the current hit, rather than only
those of the instance that references the bottom level acceleration structure.

This supports the Vulkan VK_AMDX_multi_level_acceleration_structure extension,
which permits mid level acceleration structures to be placed between the top
level acceleration structure and the bottom level acceleration structures,
producing a chain of more than one instance per hit.

Extension Name
--------------

To use this extension within a SPIR-V module, the following
*OpExtension* must be present in the module:

----
OpExtension "SPV_AMDX_multi_level_acceleration_structure"
----

New Capabilities
----------------

This extension introduces two new capabilities:

----
RayTracingMultiLevelAccelerationStructureAMDX
RayQueryMultiLevelAccelerationStructureAMDX

Modifications to the SPIR-V Specification

[[acceleration_structure_levels]]
(Add a new sub-section 3.ML, Acceleration Structure Levels) ::
+
--
Each instance in the chain of acceleration structure instances traversed to
reach a hit is identified by a _level_.

The instance contained in the top level acceleration structure is at level 0.
An instance contained in a mid level acceleration structure referenced by the
instance at level _n_ is at level _n_ plus 1.

The instance at the highest level is the one that references the bottom level
acceleration structure containing the geometry that was hit. It is referred to
as the _final instance_.

The number of levels for the current hit is available from the
<<HitInstanceLevelAMDX, *HitInstanceLevelAMDX*>> builtin in the ray tracing pipeline
execution models, and from the
<<OpRayQueryGetIntersectionInstanceLevelAMDX, *OpRayQueryGetIntersectionInstanceLevelAMDX*>>
instruction for ray queries. The level of the final instance is therefore that
count minus one.

Where an instruction in this extension takes a 'Level' operand, behavior is
undefined if 'Level' is greater than or equal to the number of levels for the
hit or intersection being queried.

Refer to the Ray Tracing chapter of the Vulkan API specification for more details.
--

4+|[[OpGetInstanceCustomIndexAtLevelAMDX]]*OpGetInstanceCustomIndexAtLevelAMDX* +
 +
 Gets the application defined value of the instance at a given <<acceleration_structure_levels, acceleration structure level>> for the current hit. +
 +
 'Result' is the returned value, taken from the lower 24 bits of the value specified for the instance at 'Level'. The upper 8 bits of 'Result' are zero. +
 +
 'Result Type' must be a 32-bit 'integer type' scalar. +
 +
 'Level' must be a 32-bit 'integer type' scalar. +
 +
 This instruction is allowed only in *IntersectionKHR*, *AnyHitKHR*, and *ClosestHitKHR* execution models. +

 This instruction is allowed only in *IntersectionKHR*, *AnyHitKHR*, and *ClosestHitKHR* execution models. +

Validation Rules
----------------

An OpExtension must be added to the SPIR-V for validation layers to check
legal use of this extension:

----
OpExtension "SPV_AMDX_multi_level_acceleration_structure"
----

Interactions with SPV_KHR_ray_tracing
-------------------------------------

The *RayTracingMultiLevelAccelerationStructureAMDX* capability, the
*HitInstanceLevelAMDX* builtin, and the per-level ray tracing instructions are only
supported if SPV_KHR_ray_tracing and the *RayTracingKHR* capability are
supported.

Interactions with SPV_KHR_ray_query
-----------------------------------

The *RayQueryMultiLevelAccelerationStructureAMDX* capability and the per-level
ray query instructions are only supported if SPV_KHR_ray_query and the
*RayQueryKHR* capability are supported.

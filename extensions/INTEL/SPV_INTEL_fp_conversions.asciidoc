== Overview

This extension adds instructions to convert floating-point values with stochastic rounding, and to convert floating-point values and clamp the result to the nearest representable integer value.
Stochastic rounding replaces deterministic rounding behavior with a stochastic (probabilistic) rounding behavior.
Stochastic rounding is important for certain numerical algorithms, particularly those relying on small floating-point types.

=== Instructions

==== 3.3.11. Conversion Instructions

[cols="1a,1,5*",width="100%"]
|=====
6+|[[OpStochasticRoundFToFINTEL]]*OpStochasticRoundFToFINTEL*

Convert an input value numerically from one floating point width to another
using stochastic rounding.

For finite input values, stochastic rounding is performed by adding a
pseudo-random bias value to the mantissa of the input value.
If this causes the mantissa to overflow, then the exponent of the input
value is increased by one and the mantissa bits are shifted right.
The value is then converted to the _Result Type_, rounding towards zero.

If the input value is infinity, or if the exponent overflows when converting to
_Result Type_, the result is determined as follows:
if the result is decorated with *SaturatedToLargestFloat8NormalConversionEXT* or
_Result Type_ has no representation for both NaN and infinity, the result is the
nearest representable value of _Result Type_;
otherwise, if _Result Type_ has a representation for infinity, the result is
infinity with a matching sign;
otherwise, the result is NaN.

If either the input value or the result is NaN, and _Result Type_ has no
representation for NaN, then the result is an unspecified stable value.

The pseudo-random bias values are generated with an implementation-defined
algorithm using _Seed_ as a starting point.
The algorithm is guaranteed to produce repeatable bias values when the same
value is passed for _Seed_.

The instruction may optionally return a new seed value in _Next Seed_.
When multiple stochastic rounding conversions will be performed by the same
invocation, the value returned in _Next Seed_ should be passed as _Seed_ for the
next stochastic rounding to generate good quality bias values.

_Result Type_ is the type of the converted value and must be a scalar or
vector of _floating-point type_.

_Value_ must be a scalar or vector of _floating-point type_.
It must have a wider range than the _Result Type_ and it must have the same number of components as _Result Type_.

_Seed_ must be a 32-bit scalar _integer type_.

_Next Seed_ must be a pointer to a 32-bit scalar _integer type_ in the *Function* storage class.

Results are computed per component.

=== Validation Rules

Add the following bullets to section 2.16.11, Universal Validation Rules:

* It is valid to use the *SaturatedToLargestFloat8NormalConversionEXT* decoration with *OpStochasticRoundFToFINTEL* when the _Result Type_ is *Float8E4M3EXT* or *Float8E5M2EXT*.
* It is not valid to apply the *FPRoundingMode* decoration to the *OpStochasticRoundFToFINTEL*, *OpClampStochasticRoundFToSINTEL*, or *OpClampConvertFToSINTEL* instructions.
* It is not valid to apply the *SaturatedConversion* decoration to the *OpClampStochasticRoundFToSINTEL* or *OpClampConvertFToSINTEL* instructions.

 * For conversions to the fp8 types *Float8E4M3EXT* and *Float8E5M2EXT*, the *RTE* (round to nearest even) rounding mode is supported and is the default rounding mode.
 * For conversions to the fp4 type *Float4E2M1EXT*, the *RTE* (round to nearest even) rounding mode is supported and is the default rounding mode.

== Issues

. Why do we need *OpClampConvertFToSINTEL*? Can we just reuse *OpConvertFToS* with the *SaturatedConversion* decoration?
+
--
RESOLVED: Although it would be nice to reuse *OpConvertFToS*, *OpClampConvertFToSINTEL* has two key differences that warrant an additional instruction instead:

* The only supported rounding mode for *OpClampConvertFToSINTEL* is implicitly *RTE* (round to nearest even).
This is different than the default rounding mode for other float-to-int conversions, which is *RTZ* (round toward zero).
* For NaN inputs, *OpClampConvertFToSINTEL* produces an unspecified stable value rather than converting to zero.
Note that the current implementation produces either the smallest or largest representable value depending on the most significant bit of the (NaN) input.
--

. Should it be valid to include the *SaturatedConversion* decoration on *OpClampStochasticRoundFToSINTEL* or *OpClampConvertFToSINTEL*?
+
--
RESOLVED: Due to the differing NaN behavior, it would be confusing to allow the *SaturatedConversion* decoration on *OpClampStochasticRoundFToSINTEL* or *OpClampConvertFToSINTEL*, therefore this is not valid.
--
